# MyVector 手写实现指南

> 前提：C++ 基础语法已掌握，未学 STL。
> 目标：从零写出一个支持扩容、深拷贝、迭代器、可模板化的动态数组。
> 读法：这份指南对**每一个函数**都给出两样东西——**它做什么（功能与契约）** 和 **怎么写（骨架）**。先读懂"做什么"，再填 `TODO`。

## 0. 先建立三个概念（后面每个函数都靠它们理解）

### 0.1 类不变量

一个类的"不变量"是**任何 public 函数返回后都必须成立的条件**。对这个类，只有三条：

1. `capacity_ == 0` ⟺ `data_ == nullptr`
2. `size_ <= capacity_`（永远成立）
3. `data_[0 .. size_)` 里是有效元素，`data_[size_ .. capacity_)` 是空闲槽位

**每个函数写的本质，都是"接住一个合法状态 → 改变某些东西 → 在返回前把对象恢复到合法状态"。** 想不清一个函数怎么写时，就问自己：它的输入状态是什么？输出状态必须满足哪几条不变量？

### 0.2 函数按"碰谁"分类

| 类别 | 函数 | 特点 |
|---|---|---|
| 只读 | `size` `capacity` `empty` `operator[]` `at` `front` `back` `begin` `end` | 不改变任何成员，必须是 `const` |
| 只改 size | `push_back`（不满时） `pop_back` `clear` | 容量不动 |
| 只改 capacity | `reserve` `shrink_to_fit` | 元素和 size 不动，只换存储 |
| 两者都改 | `push_back`（满时） `resize` | |
| 碰资源 | 构造 / 析构 / 拷贝构造 / `operator=` / `grow` | 涉及 `new[]` / `delete[]` |

这个表就是理解所有函数的框架：**先确定它属于哪一类，就能推出它该动哪些成员、不该动哪些成员。**

### 0.3 前置条件与后置条件（契约）

- **前置条件**：调用者必须保证的事。违反它是调用者的错，函数不做检查（比如 `operator[]` 越界）。
- **后置条件**：函数保证做到的事（比如 `push_back` 后 `size_` 一定大了 1，且原元素一个不少）。
- `at()` 是例外：它把前置条件变成了运行时检查，违反了就抛异常。

### 0.4 全部成员函数功能速查表

| 函数 | 功能（一句话） | `size_` | `capacity_` | 堆内存操作 |
|---|---|---|---|---|
| `MyVector()` | 创建空容器 | 0 | 0 | 不分配 |
| `MyVector(n)` | 创建容量为 n 的空容器 | 0 | = n | 分配 |
| 拷贝构造 | 用 other 的内容创建**独立**副本 | = other | ≥ size | 分配 |
| `operator=` | 让对象持有 other 内容的独立副本 | = other | ≥ size | 释放旧的 + 分配新的 |
| 析构 | 释放堆内存 | — | — | 释放 |
| `size` / `capacity` / `empty` | 只读查询 | 不变 | 不变 | 无 |
| `operator[]` | 无检查的随机访问 | 不变 | 不变 | 无 |
| `at` | 有检查的随机访问，越界抛异常 | 不变 | 不变 | 无 |
| `front` / `back` | 返回首 / 尾元素的引用 | 不变 | 不变 | 无 |
| `begin` / `end` | 给出区间 `[begin, end)` | 不变 | 不变 | 无 |
| `push_back` | 尾部追加元素，满了先扩容 | +1 | 可能翻倍 | 可能重建 |
| `pop_back` | 删除尾部元素 | −1 | 不变 | 无 |
| `clear` | 逻辑清空所有元素 | 0 | 不变 | 无 |
| `reserve(n)` | 保证容量至少为 n | 不变 | ≥ n（只增不减） | 可能重建 |
| `resize(n)` | 把有效元素个数设为 n | = n | 可能需要增 | 可能重建 |
| `shrink_to_fit` | 请求把容量缩到 size | 不变 | → size | 可能重建 |
| `grow(n)`（私有） | 按新容量重建存储并搬运元素 | 不变 | = n | 分配 + 释放 |
| `swap`（私有） | O(1) 交换两对象的资源 | 互换 | 互换 | 无 |

## 步骤 1：画内存模型，写出类声明

### 思路

动态数组 = **堆上一块连续内存** + **几个记录状态的整数**。

```
MyVector 对象（栈上）              堆内存
┌────────────────┐
│ data_     ─────┼──→ ┌────┬────┬────┬────┬────┐
│ size_     = 3  │     │ 10 │ 20 │ 30 │ ?? │ ?? │
│ capacity_ = 5  │     └────┴────┴────┴────┴────┘
└────────────────┘      └──── 已用 ───┘└─ 空闲 ─┘
```

三个成员的含义：

| 成员 | 含义 | 不变量 |
|---|---|---|
| `int* data_` | 堆数组首地址 | 空容器为 `nullptr` |
| `std::size_t size_` | 有效元素个数（用户视角） | `size_ <= capacity_` |
| `std::size_t capacity_` | 已分配空间能装多少个 | `capacity_ == 0` ⟺ `data_ == nullptr` |

**`size` 和 `capacity` 是两个不同的东西**，把这条刻进脑子，后面的 bug 大多源于混淆它们。

```cpp
    const int* end()   const;
```

## 步骤 2：RAII 四件套

### 思路

持有 `new[]` 出来的裸指针，就必须回答四个问题：**谁申请、谁释放、拷贝时怎么办、赋值时怎么办**。

**为什么编译器默认的拷贝是错的？** 默认拷贝是**浅拷贝**：只把 `data_` 指针值抄一份。结果两个对象指向同一块堆内存，析构时同一块内存被 `delete[]` 两次 → 崩溃（double free）。所以必须自己写**深拷贝**：申请新内存，逐个搬元素。

拷贝赋值的两个坑：
1. **自赋值** `a = a`：先删自己再拷自己，读到已释放内存。
2. **异常安全**：先 `delete[]` 再 `new`，一旦 `new` 抛异常，对象就半死了。

推荐 **copy-and-swap**：参数按值传 → 进来时已是一份深拷贝 → 和自己的成员交换 → 老资源随参数析构自动释放。自赋值天然安全，异常也安全。

### 函数功能说明

| 函数 | 功能 | 前置 / 后置条件 |
|---|---|---|
| `MyVector()` | 建立一个"什么资源都没有"的合法对象 | 后置：三条不变量全部成立，`data_ == nullptr` |
| `MyVector(n)` | 预先分配 n 个槽位，但一个元素都没有 | 后置：`capacity_ == n`、`size_ == 0`；`n == 0` 时不分配 |
| `~MyVector()` | 对象消失时交还堆内存 | 后置：不再持有任何堆内存 |
| 拷贝构造 | 造一个"内容和 other 一样，但存储完全独立"的对象 | 后置：值逐个相等，`data_ != other.data_`，修改互不影响 |
| `operator=` | 把当前对象改造成 other 的独立副本 | 前置：无（自己赋值给自己也必须正确）；后置：旧内存已释放，内容等于 other，存储独立 |

## 步骤 3：扩容 + `push_back`

### 思路

`push_back` 的逻辑只有两步：满了就扩容，然后放进去。真正的考点在扩容：

- **倍数扩容**（×2 或 ×1.5）：为什么不能每次 +1？因为 n 次 push 的总代价会变成 O(n²)。按倍数扩，均摊到每次 push 是 O(1)。
- **执行顺序（异常安全的关键）**：`new` → 拷贝旧元素 → `delete[]` 旧内存 → 更新指针和容量。**绝不能**先删后建。
- **初始容量为 0**：`0 × 2 = 0` 会死循环，给个下限（比如 4）。

### 函数功能说明

| 函数 | 功能 | 关键约束 |
|---|---|---|
| `grow(newCap)` | 申请一块能装 newCap 个元素的新内存，把现有 `size_` 个元素搬过去，释放旧内存 | **前置：`newCap >= size_`**（否则会丢元素）；后置：`capacity_ == newCap`，`size_` 和元素值不变 |
| `push_back(v)` | 在尾部追加一个元素 v | 后置：`size_` 增 1，`data_[size_-1] == v`，原有元素不变；满时先扩容 |

## 步骤 4：基础接口

### 思路

这些是"读状态"和"简单修改"，几行就能完成，但要理解语义：

- `pop_back`：只把 `size_` 减 1，不释放内存。对 `int` 无需真正销毁；将来 `T` 是类时，理论上应显式调用其析构函数。
- `clear`：`size_ = 0`，**容量不变**。因为 `clear` 之后再 push 不该重新扩容。
- `operator[]`：**不检查越界**，快，越界是未定义行为。
- `size / capacity / empty`：只读，必须是 `const` 成员函数，否则 const 对象调不了。

### 函数功能说明

| 函数 | 功能 | 说明 |
|---|---|---|
| `size()` | 返回 `size_` | 用户视角的元素个数 |
| `capacity()` | 返回 `capacity_` | 无需扩容还能装多少 = capacity − size |
| `empty()` | `size_ == 0` | 不是"有没有内存" |
| `operator[](i)` | 返回 `data_[i]` 的引用 | 前置：`i < size_`；违反 = 未定义行为；返回引用是为了能 `v[i] = x` |
| `pop_back()` | 删除最后一个元素 | 前置：`!empty()`；后置：`size_` 减 1，容量不变，不释放内存 |
| `clear()` | 逻辑清空所有元素 | 后置：`size_ == 0`，`capacity_` 不变 |

## 步骤 5：进阶接口

### 思路

- `reserve(n)`：只改 **capacity**，不动 size。`n <= capacity_` 时直接返回（标准允许不缩）。
- `resize(n)`：改 **size**。变大时新元素补默认值；变小时只改 size 不释放容量。
- `at(i)`：越界**抛异常** `std::out_of_range`（`#include <stdexcept>`）。这就是它和 `operator[]` 的唯一区别——STL 两者都给，让调用者选"性能"还是"安全"。
- `front` / `back`：空容器调用是未定义行为，要不要自己加断言由你决定。
- `shrink_to_fit()`：把 capacity 缩到 size。成本高（一次重新分配 + 拷贝），所以标准说它是"请求"不是"保证"。

### 函数功能说明

| 函数 | 功能 | 后置条件 |
|---|---|---|
| `reserve(n)` | 保证容量至少为 n，不改变元素 | `capacity_ >= n`，且 **size_ 和元素全不变** |
| `resize(n)` | 把有效元素个数设为 n | 变大：新增元素值初始化（0）；变小：尾部元素逻辑丢弃；capacity 只在需要时增 |
| `at(i)` | 带检查的访问 | 越界抛 `std::out_of_range` |
| `front()` | 第一个元素的引用 | 前置：非空 |
| `back()` | 最后一个元素的引用 | 前置：非空；注意 `size_-1` 的无符号下溢 |
| `shrink_to_fit()` | 请求把容量缩到 size | 可能发生，也可能不发生（标准允许） |

**`reserve` 和 `resize` 的区别（最容易混）**：`reserve` 只买坑位（capacity），`resize` 改变元素数量（size）。`reserve(100)` 之后 `size()` 仍是 0，访问 `v[0]` 依然越界。

## 步骤 6：迭代器 + 范围 for

### 思路

只要内存连续，最合法、最简单的迭代器就是**裸指针本身**。`begin()` 返回首地址，`end()` 返回"最后一个元素的下一个位置"——这是 C++ 半开区间 `[begin, end)` 的约定。

做完这一步，`for (int x : v)` 就自动能用了，你也就理解了 STL 迭代器的本质。**const 版本必须一起写**，否则 const 对象无法遍历。

### 函数功能说明

| 函数 | 功能 | 后置条件 |
|---|---|---|
| `begin()` | 返回指向第一个元素的指针 | 空容器时等于 `end()` |
| `end()` | 返回最后一个元素**之后**的位置 | 永远不指向有效元素，不可解引用 |
| const 版本 | 同上，但返回 `const int*`，只能读 | 让 const 对象也能遍历 |

范围 for 会被编译器展开成：`auto b = v.begin(); auto e = v.end(); for (; b != e; ++b) { int x = *b; ... }`——所以只要 `begin/end`、`!=`、`++`、`*` 都存在，语法就成立。指针天生满足这些。

### 代码提示 6.1

```cpp

int*       MyVector::end()         { /* TODO: return data_ + size_; */ } // 首元素 + size 个位置

```

### 自测

```cpp

for (int x : v) sum += x;         // 范围 for
```

## 步骤 7：测试 + 内存检查

### 思路

功能测试只能用 `assert` 证明"行为对"，但**内存错误不一定会崩溃**，必须借助工具。

### 代码提示 7.1 —— `Main.cpp` 测试骨架

```cpp
#include <iostream>
#include <cassert>
#include <stdexcept>
#include "Myvector.h"

int main()
{
    // 1. 基本：空容器
    MyVector v;
    assert(v.size() == 0 && v.empty());

    // 2. 扩容：100 次 push，元素顺序正确
    for (int i = 0; i < 100; ++i) v.push_back(i);
    assert(v.size() == 100 && v[99] == 99);

    // 3. 深拷贝：改副本不影响原对象
    MyVector copy(v);
    copy[0] = 999;
    assert(v[0] == 0);

    // 4. 自赋值：不崩溃且内容不变
    MyVector& ref = copy;
    copy = ref;
    assert(copy.size() == 100);

    // 5. 异常：at 越界抛 out_of_range
    bool thrown = false;
    try { v.at(1000); }
    catch (const std::out_of_range&) { thrown = true; }
    assert(thrown);

    std::cout << "all tests passed\n";
}
```

## 步骤 8：模板化

### 思路

`int` 版全部测试通过之后，再动手改模板。需要改的只有一件事：**所有地方把 `int` 换成 `T`**。但随之而来一个必然踩的坑：

**模板的成员函数定义不能放在 `.cpp` 里。** 编译器实例化模板时必须看到完整定义，而 `.cpp` 是独立编译单元——`main.cpp` 只看到声明，链接时找不到符号，你会得到一堆 unresolved external。三种解法：

1. 全部实现写进头文件（STL 和绝大多数库的做法，推荐）；
2. 显式实例化（只为已知类型服务）；
3. 文件改名 `.hpp` / `.tpp` 被头文件包含（本质还是方案 1）。

### 模板化后每个函数的新要求

| 函数 | 对 `T` 的要求 |
|---|---|
| 构造 / 析构 | 无（`new T[n]` 会默认构造 n 个元素） |
| 拷贝构造 / `operator=` | `T` 可拷贝（copy ctor、copy assign） |
| `resize` 变大 | `T` 可默认构造 |
| `push_back` 参数 | 目前按值 `T`，要求可拷贝；学完移动语义后可改 `const T&` / `T&&` |
| 其余只读函数 | 无要求 |

这些"对 T 的要求"就是将来 STL 文档里写的 **Requirements / Concepts** 的雏形。

### 代码提示 8.1 —— `Myvector.h` 改造

```cpp
#pragma once
#include <cstddef>
#include <stdexcept>
#include <utility>

template <typename T>
class MyVector
{
public:
    // 声明部分原样保留，int → T
    // ...
private:
    void grow(std::size_t newCap);
    void swap(MyVector& other) noexcept;

    T*          data_;
    std::size_t size_;
    std::size_t capacity_;
};

// 每个类外定义前面都要加 template 行，类名后带 <T>：

MyVector<T>::MyVector()
    : data_(nullptr), size_(0), capacity_(0)
{
}

template <typename T>
MyVector<T>::~MyVector()
{
    delete[] data_;
}

// ... 其余函数按同样格式逐个搬过来 ...
```

然后把 `MyVector.cpp` 的内容全部删掉（保留空文件或直接删除并从编译列表里去掉）。
